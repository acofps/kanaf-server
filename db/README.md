# تشغيل قاعدة البيانات ولوحة الإدارة — دليل عملي

هذا الدليل مكتوب لسيرفرك الخاص (VPS) اللي عندك وصول جذر (root) عليه — الأوامر أدناه صحيحة بالضبط لهذا السياق.

## 1. تثبيت PostgreSQL (مرة وحدة)

```bash
apt-get update
apt-get install -y postgresql postgresql-contrib
service postgresql start
systemctl enable postgresql   # يشتغل تلقائياً بعد أي إعادة تشغيل للسيرفر
```

## 2. إنشاء قاعدة البيانات والمستخدم

```bash
su postgres -c "psql -c \"CREATE USER marsa WITH PASSWORD 'كلمة_مرور_قوية_حقيقية';\""
su postgres -c "psql -c \"CREATE DATABASE marsa OWNER marsa;\""
```

**لا تستخدم كلمة المرور التجريبية اللي بأي مثال هنا — ولّد وحدة حقيقية:**
```bash
openssl rand -base64 24
```

## 3. تطبيق المخطط (schema)

```bash
cd marsa-server
PGPASSWORD='كلمة_مرورك' psql -h localhost -U marsa -d marsa -f db/schema.sql
```

هذا يبني كل الجداول دفعة وحدة — **تحققت من هذا الأمر فعلياً على قاعدة PostgreSQL 16 حقيقية أثناء البناء، ونجح بدون أي خطأ.**

## 4. إعداد `.env`

انسخ `.env.example` إلى `.env` واملأ:
```
DATABASE_URL=postgresql://marsa:كلمة_مرورك@localhost:5432/marsa
ADMIN_JWT_SECRET=<ولّد وحدة: openssl rand -hex 32>
```

**لا تستخدم القيمة الافتراضية بـ`ADMIN_JWT_SECRET` أبداً** — الخادم يرفض يشتغل لو تركتها كما هي (تحقق أمان مبني بالكود نفسه، جرّبته: السيرفر يطبع خطأ ويتوقف فوراً).

## 5. إنشاء أول حساب "مالك" (owner)

```bash
node db/seed_first_admin.js "اسمك الكامل" "بريدك@موقعك.com" "كلمة مرور 15 حرف فأكثر"
```

هذا سكربت طرفية (CLI) بس — **مو مسار API مفتوح**، عمداً، عشان محد يقدر ينشئ حساب مالك من الويب.

## 6. تشغيل السيرفر باستمرار (PM2)

```bash
npm install -g pm2
cd marsa-server
pm2 start index.js --name marsa-backend
pm2 save
pm2 startup   # ينفّذ أمر يخلي PM2 يشتغل تلقائياً بعد أي إعادة إقلاع للسيرفر
```

## 7. الأدوار المتاحة (roles)

| الدور | الصلاحيات |
|---|---|
| `support` | يشوف لوحة القيادة (أرقام إجمالية بس)، قائمة المستخدمين الأساسية، الرسائل |
| `content_manager` | كل شي فوق + يقدر يشوف حالة اعتماد المحتوى |
| `admin` | كل شي فوق + يشوف بيانات حساسة (بسبب موثّق إجباري)، يعتمد المحتوى، يفعّل/يوقف رحلة أو دفتر |
| `owner` | كل شي فوق + يوافق على طلبات break-glass، يشوف سجل الوصول الكامل |

غيّر دور أي حساب لاحقاً مباشرة بقاعدة البيانات:
```sql
UPDATE admin_users SET role = 'admin' WHERE email = 'someone@example.com';
```

## 8. سياسة الحذف (deletion policy) — نقطة مهمة

جدول `users` فيه عمود `deleted_at` (soft delete) بدل حذف فوري نهائي. لازم تضيف **مهمة مجدولة (cron)** تحذف نهائياً الصفوف اللي `deleted_at` فيها أقدم من فترة معينة (مثلاً 30 يوم) — هذا يحقق بالضبط التوازن اللي ناقشناه بالمراجعة الهندسية: حذف فوري من منظور المستخدم (يوقف كل استخدام لبياناته)، مع نافذة قصيرة قبل المسح النهائي تحسباً لأي حاجة نظامية (نزاع دفع، طلب قانوني).

مثال cron (يومياً الساعة 3 فجراً):
```
0 3 * * * psql "$DATABASE_URL" -c "DELETE FROM users WHERE deleted_at < now() - interval '30 days';"
```

## 9. تفعيل RLS (Row-Level Security) — خطوة لاحقة، مو الآن

`schema.sql` فيه سياسات RLS جاهزة **لكن معطّلة (commented out)** لأنها تحتاج الخادم يتصل بقاعدة البيانات عبر دور Postgres مخصص لكل طلب (مو دور واحد ثابت لكل التطبيق). هذي خطوة تحسين أمان حقيقية، بس تحتاج تعديل بكيفية اتصال `db/pool.js` بالقاعدة — أخبرني لما توصل لهذي المرحلة ونبنيها مع بعض.

## 10. ما لسا ناقص (بصراحة كاملة)

- **بوابة الدفع** (Moyasar/Tap/HyperPay) — الجداول (`subscriptions`, `invoices`) جاهزة تستقبل البيانات، بس endpoint الدفع نفسه لسا ما بنيناه.
- **واجهة لوحة التحكم نفسها** (الفرونت إند اللي يعرض هذي البيانات) — اللي بنيناه الحين APIs بس، مو واجهة مستخدم.
- **RLS مفعّلة فعلياً** — البنية جاهزة، التفعيل لسا معلّق (نقطة 9 أعلاه).
