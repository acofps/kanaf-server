# البث الجماعي — إيميل حقيقي، مو إشعار داخل التطبيق

## نقطة توضيح مهمة
هذي **رسائل إيميل حقيقية** تصل صندوق وارد المستخدم، عبر Resend. **مو مربوطة** بجرس الإشعارات جوّا تطبيق المستخدمين — ذاك محلي بالكامل بالمتصفح، بدون أي تزامن مع الخادم حالياً (نفس الفجوة الموثّقة بمراجعات سابقة).

## تحققت من هذي النقطة قبل ما أبني أي كود
بحثت بتوثيق Resend الرسمي ولقيت حدين مهمّين:
- **2 طلب بالثانية بس** كحد أقصى — حلقة تكرار ساذجة (إرسال إيميل واحد بكل نداء) بتفشل بسرعة مع أي عدد مستخدمين حقيقي.
- **Resend عندها endpoint حقيقي للإرسال الجماعي** (`/emails/batch`) يرسل حتى 100 إيميل بنداء وحد، وكل مستلم يوصله إيميله الخاص (مو "نسخة للكل" تكشف بريد الجميع لبعض).

بنيت التقسيم والتأخير بينهم على هذا الأساس، **واختبرته فعلياً بـ250 مستلم وهمي** — تأكدت إنه ينقسم بالضبط لـ3 نداءات (100+100+50) بتوقيت صحيح بينهم.

## الحماية المهمة بالواجهة
البث الجماعي **صعب التراجع عنه بعد الإرسال** — ولذا بنيت خطوتين إلزاميتين: معاينة كاملة (العنوان، النص، وعدد المستلمين الفعلي المجلوب من قاعدة البيانات مباشرة) قبل أي زر "تأكيد إرسال".

## الفئات المتاحة
كل المستخدمين، المشتركين النشطين بس، أو غير المشتركين (تجربة/مجاني) — اختبرت الثلاثة فعلياً ببيانات حقيقية مختلطة، وطلعت الأعداد صحيحة تماماً لكل فئة.
